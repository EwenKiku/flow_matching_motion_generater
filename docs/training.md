# 训练流程

本文描述当前仓库里条件流匹配轨迹生成器的训练过程，以及推理时一帧 `base_link` 位姿和关节是如何拼出来的。训练部分包括输入、片段加载、监督目标、网络预测量和足部运动监督。默认机器人是 RP1，配置在 `configs/rp1.yaml`。Pi Plus 使用同一套算法，只是骨架、足底几何和训练步数不同。

实现入口是 `scripts/train.py`。算法在 `motion_flow/`，机器人差异在 `configs/`。

## 1. 训练在预测什么

启用 model.root_residual 时，模型同时学习实测根相对平滑指令轨迹的水平偏移和偏航。GT 在整段动作上对世界 xy 与展开后的偏航做中心高斯平滑（标准差 0.15 秒），再将平移差转入每帧的指令朝向坐标系。

网络生成未来 30 帧（50 Hz 下为 0.6 秒）的姿态残差。姿态通道是：

| 通道 | 含义 |
| --- | --- |
| `z` | 锚点机体高度，RP1 的锚点是 `base_link` |
| `roll`、`pitch` | 锚点机体的横滚、俯仰，单位弧度 |
| 接下来 dof 个通道 | 配置 `joints` 顺序下的铰链角，单位弧度 |

RP1 是 24 个铰链，另有三个根偏移通道，姿态维度是 30。Pi Plus 是 22 个铰链，姿态维度是 25。残差先投影到 8 个正弦模态上，流匹配回归的是这些模态系数从噪声走到数据的速度。

## 2. 启动与配置

```bash
conda activate flow_matching
python scripts/train.py --robot rp1 --data data/rp1
```

不写 `--robot` 时读取 `configs/rp1.yaml`。命令行里的 `--data`、`--pattern`、`--max-clips`、`--steps`、`--batch-size`、`--lr`、`--seed`、`--log-interval`、`--threads`、`--out`、`--device` 会盖过配置。检测到 CUDA 时默认用 GPU。

RP1 的训练超参：

| 项 | 值 |
| --- | --- |
| 优化步数 | 500000 |
| batch | 64 |
| 学习率 | 4e-4，余弦退火到 4e-5 |
| 梯度裁剪 | 全局范数 1 |
| 历史 / 未来 | 15 / 30 帧 |
| 风格窗口 | 1 到 5 秒 |
| 模态数 | 8 |
| 网络宽度 / 层数 / 头数 | 96 / 3 / 4 |
| `flow_weight` | 5 |
| `slip_weight` | 10 |
| `arm_mix_prob` | 0.2 |
| `feet.contact_height` | 0.025 m |

Pi Plus 的 `train.steps` 是 10000，默认关闭手臂混合。

## 3. 原始输入

每条样本来自 reactor_mjlab 导出的一个 NPZ。RP1 的目录 `data/rp1` 指向 `/home/kiku/data/RL/reactor_mjlab/outputs/rp1`，约 21406 个文件，50 Hz。

`load_clip` 从 NPZ 读出这些字段：

- `fps`，必须与配置一致
- `joint_names`，集合必须和配置的 `joints` 相同，数值按配置顺序重排
- `body_names`，必须与配置的 `bodies` 完全一致，包括重复名
- `anchor_body`，RP1 与 Pi Plus 都是 `base_link`
- `quaternion_order`，`wxyz` 或 `xyzw`
- `body_pos_w`、`body_quat_w`，只取锚点刚体
- `joint_pos`

锚点四元数换成内旋 `xyz` 的横滚、俯仰、偏航。落成内存里的一条 `Clip`：

- `pose`：`(帧数, 3 + 铰链数)`，即高度、横滚、俯仰、铰链角
- `xy`：锚点在世界系的水平位置
- `yaw`：锚点偏航

空片段、非有限数值、退化四元数、帧率或骨架不匹配都会直接拒绝该文件。短于 `history + future`（45 帧）的片段读进来之后不进入训练集。

## 4. 数据加载

`load_training_set` 用配置里的 `train.pattern` 递归匹配动作目录。默认是 `*.npz`。`max_clips` 为 0 时全部保留；为正数时先打乱再截断。

加载时锁定第一份成功文件的关节名和刚体名单，后面的文件必须与之相同。进度每 500 个文件打印一次。

全部片段进内存之后，先按 `val_fraction` 划出验证片段。归一化只用训练片段的逐通道均值和标准差：

```text
mean = 所有帧 pose 的均值
scale = max(标准差, 0.025)
```

`0.025` 是下限，避免近乎不变的通道把归一化放大到数值不稳定。`mean` 和 `scale` 存在网络 buffer 里，会随权重一起保存。历史、风格和未来姿态在进网络前都做 `(pose - mean) / scale`。根的 `xy` 和偏航不参与这组矩。

## 5. 一条训练样本如何构成

每个优化步调用一次 `sample_training_batch`。一个 batch 共享同一个风格时长，在 1 秒到 `style_seconds` 之间均匀抽取整数帧。50 Hz、5 秒时，这个长度是 50 到 250 帧。

对 batch 里的每一条：

1. 均匀抽取一个片段。
2. 在片段里均匀抽取起点，使后面能放下 15 帧历史和紧接着的 30 帧未来。记历史结束、未来开始的那一帧为 `split`。
3. 再取一段风格。优先放在预测窗口之外：要么完全落在历史起点之前，要么完全落在未来终点之后。片段太短、放不下不相交窗口时，才允许和预测窗口重叠。风格短于本 batch 的统一长度时，用边缘值补齐，并记下有效帧掩码。
4. 未来根路径写成相对 `split - 1` 那一帧的局部量。原点是该帧的 `xy`，朝向是该帧的偏航。未来每一帧保存 4 个数：局部 `x`、局部 `y`、`sin(相对偏航)`、`1 - cos(相对偏航)`。

因此一条样本有五块，也是 `MotionFlow.loss` 的前五个参数：

| 张量 | 形状（RP1） | 角色 |
| --- | --- | --- |
| `past` | `(64, 15, 34)` | 历史姿态，网络条件 |
| `style` | `(64, L, 30)` | 风格姿态，`L` 为 50 到 250 |
| `valid` | `(64, L)` | 风格补齐位置为 False |
| `path` | `(64, 30, 4)` | 未来根的局部平面路径 |
| `future` | `(64, 30, 30)` | 未来姿态，流匹配和足部运动的监督 |

`future` 就是姿态监督。RP1 的 path 是指令条件，future 的末三维是骨盆偏移监督。

训练时，符合移动速度和腿部活动门槛的窗口有一半机会做恒定倍率时间重采样（0.8–1.25 倍，受片段末端限制），姿态和根路径使用相同的时间索引。RP1 有 20% 的机会从另一训练片段取连续手臂动作，覆盖历史与未来，并从同一供体取手臂风格。根、腰和腿保留原动作。验证统一使用原始时间轴和原始上下肢组合。

训练使用与姿态配对的实测根轨迹，保留换重心时的侧移和转动。

RP1 的 `train.generated_history_prob` 默认 0.25。接续批次使用至少 65 帧的训练片段，先生成并采用前 20 帧，再取末尾 15 帧作为下一窗口历史。第二窗口的根路径以交界帧重新定向，参考足速使用 GT 交界姿态。梯度来自第二窗口，第一窗口只采样。设为 0 可复现全真实历史训练。

## 6. 条件是怎么编码的

姿态在归一化之后才进入编码器。历史拼上自己的帧间差分，差分乘以 5。风格的帧差同样乘以 5，再除以这段风格自己的根速度，下限是 0.15 m/s。这样风格保留的是每米大约怎么动，记录时的快慢不再写进风格向量。推理切换风格时用同一套除法。

风格编码器每 4 帧取一个 token，前面加一个可学习的 register。两层 Transformer 只从 register 读出向量，再做成单位范数嵌入。有效帧的平均姿态单独保留，后面用来做基线。补齐帧不进入平均，也不参与注意力。

RP1 启用 `model.link_history`。历史张量末四维是名义根路径特征，结合骨盆偏移还原真实根位置与航向后，用 MJCF 正向运动学计算所有 link。每帧的位置以历史末帧骨盆为原点，旋转和位置均按末帧水平朝向对齐，保留重力方向。每个 link 的三维位置与旋转矩阵前两列映射为每帧的附加嵌入，历史原有姿态和差分也参与编码。

历史是 15 个 token，加上正弦位置编码。训练时每个样本有 15% 的概率把整段历史 token 乘零，迫使网络在缺少近期姿态时仍能靠风格和根路径生成。

根路径不逐帧送入。未来 30 帧里取下标 `2, 5, ..., 29` 共 10 个结点。每个结点是 7 维：局部 `xy`、偏航的正弦余弦形式，以及相对上一结点的平面扭转。扭转乘以 `fps / 3`，把 3 帧间隔换成每秒量级。这 10 个 token 也加位置编码。

风格嵌入乘以 `sqrt(width)` 后映射成 1 个 token，拼在历史和路径 token 前面。生成器是 3 层 pre-norm Transformer，宽度 96，4 头，前馈隐藏维 288，激活是 GELU。

基线不由速度场学习。它是从历史最后一帧线性走到风格平均姿态的 30 帧直线：

```text
baseline(t) = past[-1] + (t / 30) * (style_mean - past[-1])
```

这里的 `t` 是未来帧序号 1 到 30，和下面的流时间不是同一个量。

## 7. 流匹配的监督目标

未来姿态先减去基线，再乘模态基的伪逆，得到 8 个系数。这就是流匹配要到达的目标 `a`，形状为 `(batch, 8, 30)`。

模态基是锚定正弦：

```text
basis[frame, k] = sin(pi * frame * (k + 0.5) / 30.5) / (k + 1)^1.5
```

`frame` 从 1 计到 30，所以窗口起点的位移是 0，终点自由。除以 `(k + 1)^1.5` 让高频模态幅度更小。8 个模态不能完整重构 30 帧，伪逆给出的是最小二乘系数。推理解码用的是同一组基，因此损失和播放看到的是同一个低频子空间。

流时间 `t` 在 `(0, 1)` 上均匀抽取，噪声 `e` 是标准正态，和 `a` 同形。直线插值状态是：

```text
x = (1 - t) e + t a
```

回归目标是常数速度 `a - e`。网络输出由两部分相加：高斯插值的解析速度，加上 Transformer 从最后 8 个模态 token 读出的残差。解析项是

```text
((2t - 1) / (t^2 + (1 - t)^2)) * x
```

流匹配损失是预测速度和 `a - e` 的加权均方。第 `k` 个模态的权重是 `1 / sqrt(k)`，再除以权重均值，使加权后的总权重仍是 1。低频模态承担步幅和大幅度姿态，权重更高。这项再乘配置里的 `flow_weight`。

日志里的 `flow` 是乘过 `flow_weight` 之后的值。

## 8. 解码后的姿态约束

流匹配直接约束的是模态速度。支撑脚和关节损失要看具体姿态，所以先用当前预测速度做一步去噪，得到干净系数的估计：

```text
clean = x + (1 - t) * predicted_velocity
pose = (baseline + basis @ clean) * scale + mean
```

`pose` 回到物理单位。历史最后一帧和未来监督也反归一化，分别作为锚点姿态和参考姿态。参考姿态就是第 5 节的 `future`，不是模态重构。

参考足跟与前掌连续两帧的高度确定支撑权重。支撑期惩罚预测点水平速度，摆动期匹配参考点的三维速度，包含历史末帧到预测首帧。接触过渡用连续权重混合两项，速度单位为 m/s。

## 9. 总损失和优化

总损失为 `flow_weight * flow + slip_weight * foot + drift_weight * drift`。流匹配监督整个姿态序列的模态，足部损失通过机器人正向运动学回传梯度。

优化器是 AdamW，学习率按余弦从 `lr` 降到 `0.1 * lr`。反向之后把参数梯度的全局范数裁到 1，非有限梯度会中止训练。

日志在第 1 步、每 `log_interval` 步和最后一步打印。`mean_loss` 是这个区间里总损失的平均。`flow` 和 `foot` 是当前步已加权的两个分项。

归一化矩只用训练片段计算。`val_fraction` 默认 0.05，按片段整段划出验证集，这些片段不参与训练。片段少于 2 条时不划验证集。

每 `save_interval` 步（默认 5000）以及最后一步，当前权重原子替换到配置里的 `checkpoint`。RP1 默认是 `checkpoints/rp1.pt`。同一步在验证片段上再抽 `val_batches` 个 batch（默认 16），模型处于 eval，历史丢弃关闭，损失定义与训练相同。在最多四条固定验证片段上，用对应指令路径的速度连续生成最多三个规划步幅。闭环世界足部位置 RMSE 低于历史最好值时，另存 `checkpoints/best.pt`。文件里有网络配置、`state_dict`（含归一化矩）、关节顺序、刚体名单、机器人名、步数、随机种子、文件名通配和片段数。生成时如果机器人、关节顺序或刚体名单和当前配置不一致，会拒绝加载。

## 10. 推理时一帧是怎么拼出来的

RP1 输出高度、横滚、俯仰、24 个关节角和三个骨盆偏移。每次重规划都在持续积分的指令路径上采样。输出帧将局部水平偏移旋转至世界系并加到指令位置，偏航差加到指令朝向，再结合横滚和俯仰构造四元数。历史保留网络输出的完整通道。旧权重及默认 Pi Plus 配置直接使用积分位置和航向。

风格 NPZ 按最多 5 秒一段编码，多段嵌入按时长加权后再归一化。每隔配置的 stride 帧重新采样一次，从新计划首帧开始直接输出。指令相对上次规划的任一分量变化超过 `replan_delta`（0.15），或切换风格时，提前重规划。切换风格不重置已经积分出来的根轨迹。

`slip`、`joint`、`step` 只出现在训练。推理不根据这三项修改输出，也不再做足端贴地。

RP1 的 drift 项以参考足跟或前掌低于接触阈值的连续区间为单位，比较每帧相对区间起点的水平位移与参考位移，按有效点帧平均平方误差（平方米）。窗口起点已接触时以历史末帧起算。drift 日志含权重，设 train.drift_weight 为 0 可关闭。
